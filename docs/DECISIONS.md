# Decisions

Every judgement call the specification left open, one paragraph each. Newest at the
bottom.

## Workspace and tooling

- **Single workspace, three crates.** `protocol` (pure codecs, no I/O), `server`
  (all listeners and state) and `client-sim` (test/demo client). This matches the
  layout in AGENTS.md section 4 and keeps the wire contract in a crate that has no
  dependencies on the runtime.
- **`tokio-tungstenite` as a dev-dependency of `server`.** `axum` can serve
  WebSockets but ships no client. Integration tests need a real WebSocket client, so
  `tokio-tungstenite` is used only under `[dev-dependencies]` and never in the
  shipped binary.
- **`rand 0.8` pinned.** `OsRng::fill_bytes` is the stable API we need for tokens and
  room codes. Newer `rand` majors moved that trait; pinning avoids churn in security
  relevant code.

## Protocol

- **JSON dispatch is manual.** The first parse is into `serde_json::Value`; the
  `"type"` string selects the concrete struct and `"rid"` is extracted separately.
  This is what lets the server distinguish `unknown_type` (forward compatibility,
  no disconnect) from `bad_message` (missing/invalid fields). Unknown JSON fields are
  ignored by serde's default behaviour, as section 6.1 requires.
- **`Room.code` is optional.** It is omitted (`null` is never sent) when the viewer is
  not allowed to see it. Public room listings always omit codes; unlisted rooms only
  reveal the code to their members. This keeps one `Room` type for every context.
- **`Room.connection` is optional and omitted until a `connection_report` arrives.**
  The example in section 6.4 shows `"direct"`, but before any report the path is
  genuinely unknown; omitting is more honest than guessing.
- **Binary frame validation lives in the codec.** The input bit layout (only bits
  0-8, direction 1-9) is a format rule, so `FeedFrame::decode` rejects violations
  with `CodecError`. The business rule "checksum tick is a multiple of 60" is left to
  the server, which can answer with an `error` without losing the frame type.
- **`docs/PROTOCOL-VECTORS.md` is generated by a test.** Running
  `cargo test -p fighter-protocol` rewrites the file, so the game team always gets
  vectors that match the current encoder. The test also asserts the two worked
  examples from section 13.1 byte for byte.
- **Room codes and tokens use `OsRng`.** Six characters from the specified alphabet
  for codes, 16 random bytes for session tokens, 8 for relay keys.

## Server (M1)

- **Central `Mutex<Lobby>` rather than an actor per room.** At the target of 5,000
  rooms and 10,000 connections, a single lock held only for synchronous state edits
  (never across an `.await`) is simpler to reason about and fast enough. Messages are
  queued into per-connection `mpsc` channels while the lock is held, then sent after
  it is released.
- **A one-second janitor task owns all expiries.** Join-request timeouts, idle-room
  expiry and coalesced `room_state` broadcasts are swept centrally against the
  injected `Clock`. This is what makes integration tests instant: the test clock is
  advanced instead of sleeping.
- **Room passwords are stored as SHA-256 and compared in constant time.** No salt in
  v1 because the password is a short shared secret checked against a single room, not
  a user credential; the hash still keeps it out of logs and memory dumps.
- **`match_session` tokens are issued in M1 but only consumed in M2.** The lobby
  flow needs to send the message and the game needs the fields, but UDP `BIND` is
  milestone 2. The tokens are generated, stored on the session and delivered; the UDP
  listener simply does not exist yet.
- **`spectate` is accepted in M1 with `match_live: false`.** Room membership, password
  and capacity rules are enforced, but the binary feed fan-out is milestone 3. This
  keeps the message contract stable across milestones.
- **`queue_join`/`queue_leave` return `not_allowed` in M1.** They are milestone 5;
  replying with a defined error is better than silently ignoring a known message.
- **Reconnection (`resume_token`) is deferred to M4.** The token is generated and
  sent in `welcome`, but a new connection does not yet adopt an old session.
- **The server crate is both a library and a binary.** Integration tests need to
  bind a real listener on a random port and hold the `AppState`, so the logic lives
  in `lib.rs` and `serve::start`, and `main.rs` is a thin wrapper. This also keeps
  the M1-M3 demo script able to reuse the same bootstrap.
- **`GET /v1/rooms` returns `{"rooms":[...]}`.** The specification says "public
  room list" without fixing the envelope; matching the WebSocket `rooms` message
  keeps one shape for websites and clients. Codes are always omitted here.
- **The janitor ticks on real time (100 ms) but reads the injected clock.** This
  lets integration tests advance a `TestClock` to exercise the 30-second join
  timeout and idle expiry in milliseconds without changing the sweep cadence.
- **Malformed-message counting uses a one-minute sliding window per session.**
  Ten `bad_message` frames inside the window close the connection with code 4000;
  `unknown_type` never counts, as section 6.1 requires forward compatibility.

## Server (M2)

- **Bindings are keyed by token and relay key, separate from rooms.** The datagram
  path resolves a session from the 16-byte token (BIND) or 8-byte relay key
  (RELAY) without walking room state, so relay stays O(1) per datagram. Slots are
  registered when a match is accepted and removed when the room closes or the
  guest leaves; the janitor also drops them after 60 s of silence or 6 hours.
- **Session tokens and relay keys are stored as raw bytes, hex-encoded for JSON.**
  `match_session` still carries the hex strings from section 6.3, but the binary
  UDP path needs the bytes, so the session keeps both forms (hex derived on demand).
- **The UDP listener sends after releasing the lobby lock.** `handle_udp` decodes,
  validates, updates budgets and resolves the destination while holding the lock,
  then returns `(addr, bytes)`; the async send happens outside. This keeps the
  lock hold time to a hash lookup and a few counters.
- **"Unauthenticated" UDP limit applies to BIND, PING and failed RELAY.** A valid
  RELAY from a bound endpoint is governed by its own 200 datagram/s and 64 KiB/s
  budget instead, because 20/s would throttle normal matches. A RELAY that fails
  authentication (unknown key, wrong source) is charged to the source-IP limit.
- **Endpoint changes re-notify peers.** A BIND from a new source port moves the
  recorded endpoint and clears the "notified" flag, so both players get a fresh
  `peer_endpoints` and the relay follows the NAT rebound.
- **No amplification is enforced in two places.** The codec property test asserts
  BOUND ≤ BIND, PONG == PING and RELAYED ≤ RELAY; the UDP listener refuses to send
  any reply larger than the datagram that caused it.

## Server (M3)

- **Spectator delivery is pull-based, not push-queued.** The server stores a
  per-tick input log with batch receive times. Every 20 ms a single task computes
  how many ticks are visible (`receive + delay <= now`) and pushes any
  not-yet-delivered inputs to each spectator, re-batched into 600-tick frames.
  Late joiners start at tick 0 and catch up naturally; live spectators advance a
  little at a time. There is one timer per server, never one per spectator.
- **The match log stores batch receive times, not per-tick times.** A `Batch`
  records the cumulative tick count and receive time of each INPUTS frame, so
  `visible_ticks` is a binary search instead of an O(ticks) scan, and the log costs
  four bytes per tick instead of twelve.
- **`MATCH_START` is immediate; everything else is delayed.** Section 8.3 says a
  late joiner gets `MATCH_START` before the backlog, so it is never delayed. This
  leaks only setup data (fighters, stage, seed), never live inputs.
- **Slow spectators are detected by send backpressure.** The flush stops queueing
  when a session's outstanding bytes reach `spectator_max_queued_bytes`; a
  spectator that cannot drain for 25 consecutive flushes (500 ms) is dropped with
  `spectate_ended` reason `too_slow`. This is deterministic and does not depend on
  kernel socket buffer sizes, unlike checking only the total backlog.
- **`spectator_max_queued_bytes` is configurable.** Default 1 MiB per section 8.3;
  tests lower it so a stalled reader is dropped quickly.

## Server (M4)

- **Reconnection keeps the session object and clears its sender.** On socket
  close the session is not removed; its `out` sender is set to `None` (which ends
  the writer task) and `disconnected_at` is stamped. A new `hello` carrying the
  `resume_token` adopts the session, gets a fresh sender and a rotated token, and
  receives `welcome` with the same `session_id` plus the current `room_state`. The
  janitor tears the session down 30 s later.
- **Resume tokens are single-use.** `try_resume` rotates the token immediately, so
  a replayed token starts a new session instead of stealing the old one.
- **Silent sessions become disconnected, not removed.** The 45 s silence check
  marks a session disconnected and gives it the same 30 s reconnect grace, so a
  transient network stall does not drop a player's room immediately.
- **Bans are per client-id-hash and per IP, in the lobby.** Ten violations
  (malformed frames or rate-limit trips) issue a 10-minute ban that doubles per
  repeat up to 24 h; strikes decay after a quiet hour. Bans are per server
  instance, matching the region-scoped architecture.
- **The blocklist lives in `[moderation].blocklist`.** It is applied to player
  names and room names and rejects with `name_invalid`; the default list is empty.
- **Relay latency is measured from UDP receive to send completion.** Exposed as the
  `fighter_relay_latency_seconds` histogram so the p99 target is verifiable from
  `/metrics`; the measured p99 is under 0.5 ms (see `docs/LOAD-TEST.md`).
- **Graceful shutdown sends a notice, then drains matches up to 60 s.** New
  connections are refused while draining; the wait is bounded by
  `limits.shutdown_grace_ms` so shutdown always completes.
- **Fuzz targets are a standalone `fuzz/` crate.** It is intentionally not a
  workspace member, so `cargo test --all` stays on stable; CI installs nightly and
  `cargo-fuzz` and runs each target for 60 s.

## Server (M5)

- **Replays are file-backed, not SQLite.** Each finished match is written as
  `{replay_dir}/{id}.replay` (the length-prefixed frame stream from section 9)
  plus a JSON `index.json`, loaded at startup. This avoids a C dependency while
  keeping the HTTP contract stable; the store is isolated in `replays.rs` so it
  can be swapped for SQLite without touching callers.
- **Feed verification compares the two logs whenever either side advances.** A
  mismatch is only reported when both logs have the same tick, so the order in
  which host and guest frames arrive cannot cause a false positive. The host's
  `MATCH_START` only clears the guest log when it names a different match.
- **Admin auth prefers an inline `admin.token` over the environment.** The spec
  configures it through `token_env`; the inline field exists so tests do not have
  to mutate process-global environment variables. Both are compared in constant
  time.
- **`feed_verified`, `stats` and the admin/regions/replay endpoints are additive
  to the wire protocol.** `feed_verified` defaults to `true` when absent, so a
  client built against an earlier revision still parses a `Room`.
- **Quick-match rooms are public and allow spectators.** The first client in the
  queue becomes host, the second guest; pairing requires the same mode, region,
  game version and content hash.
